# 背单词复习规划引擎

如果你要做一款背单词 App——比如「XX 背单词」「XX 斩」，或者你心里那个还没起名字的产品——你迟早会遇到同一个问题：**今天到底让用户背哪些词？**

这正是这个项目要解决的。它只提供一份详细的引擎业务描述文档，外加配套的数据格式和验收用例；不提供现成 App，也不绑定任何技术栈。你把仓库交给 AI，AI 就能基于这份文档帮你把产品做出来。

为什么只给文档、不给一套现成代码？因为文档的兼容性最强：今天做网页，明天做小程序，后天换 Flutter、Swift 或别的技术栈，都可以把同一份文档交给 AI，按同一套规则重新实现。

## 引擎能做什么

| 能力 | 用户看到的效果 |
|---|---|
| **每日计划** | 每天自动算出要复习哪些词、学哪些新词，总量可控 |
| **复习调度** | 根据“认识 / 模糊 / 忘记”安排下次复习；忘记的词次日再来，模糊的词不会拖太久 |
| **学习队列** | 控制复习和新词的先后顺序；当天忘记的词会按设定间隔重新出现 |
| **词汇生命周期** | 选词、退词、标记熟知、取消熟知、暂停、恢复、删除后重新加入 |
| **数据恢复** | 学习记录可导出、导入、重放；同一条操作不会重复记账 |
| **统计与预测** | 到期预测、记忆持久度、熟知度、每日学习记录 |

适合背单词 App、小程序、网页、桌面端，也适合先用 AI 生成一个可运行的原型。引擎不绑定 UI、数据库、平台或编程语言。

## 引擎不负责什么

这些属于应用层，由你和 AI 决定：

- 页面、交互和视觉设计；
- 账号、登录、支付和会员；
- 词典、释义、例句、发音和课程内容；
- 云同步、消息推送、运营和增长功能。

## 怎么让 AI 使用这个仓库

1. 把仓库文件夹或 GitHub 链接交给 AI 工具（Cursor、Claude Code、Codex 等）。
2. 复制下面的提示词，补全你的应用层描述。
3. 先让 AI 给出技术方案和模块拆分；确认后，再让它按模块实现并自测。

你不需要读引擎规范，也不需要自己拆规则。AI 会读取仓库里的设计文档、数据格式和验收用例。

### 直接复制这段提示词

```text
你是一名资深全栈工程师。这个仓库是一份背单词复习规划引擎的设计文档，
不是现成应用。请先阅读 docs/SPEC.md、schemas/v0.3/ 和
conformance/README.md，理解引擎规则、数据格式和验收标准。

工作要求：
1. 以 docs/SPEC.md 为唯一业务依据，不要修改引擎规则；
2. 数据模型遵循 schemas/v0.3/，不要擅自增删字段；
3. 不要自行发明配额、排序、同日重复和到期日规则；
4. 每完成一个模块，用 conformance 场景验证；
5. 先给技术方案、模块拆分和开发顺序，我确认后再写代码。

我的应用层：
- 平台：<Web / 小程序 / iOS / Android / 桌面端>
- 目标用户：<...>
- 核心页面：<...>
- 词库来源：<...>
- 数据存储：<本地 / 云端 / ...>
- 账号与同步：<需要 / 不需要 / ...>
- 其他要求：<...>

请先用一句话复述引擎边界，列出还需要我补充的信息，
然后给出第一版实现方案。
```

### 描述应用层时，尽量说清楚

- **平台**：网页、小程序、iOS、Android、桌面端，还是多端。
- **用户**：学生、考试备考、职场人士，还是儿童。
- **页面**：今日学习、单词卡片、词库、统计、设置，哪些必须有。
- **词库**：自带词书、用户导入、公开词典，还是需要自己整理。
- **存储**：只存本地、需要账号云同步，还是要支持多设备。
- **商业化**：免费、订阅、买断，是否要区分免费和付费功能。

这些信息不需要涉及引擎内部规则。AI 会根据你的描述，把应用层接到引擎上。

## 仓库里有什么

| 文件 | 作用 |
|---|---|
| [docs/SPEC.md](docs/SPEC.md) | 引擎设计文档：业务规则、状态、接口和边界，AI 的主要依据 |
| [schemas/v0.3/](schemas/v0.3/) | 数据结构定义：单词状态、学习事件、配置、每日计划、导入导出 |
| [conformance/](conformance/) | 验收用例：FSRS-3 数值测试和业务场景测试，AI 用来自测 |
| [.github/](.github/) | 自动检查配置，确保修改没有破坏规则 |

仓库里没有可直接上线的 App。`conformance/` 里的 Python 只用于验证规则，不是生产引擎。
