# RPE · 复习规划引擎

RPE（Review Planning Engine）是一套开源的**背单词复习规划规范**。

它不提供现成 App，而是把背单词产品最核心的规则写清楚：**什么时候复习、每天学多少、先学什么、同一个词今天出现几次**。你可以用任何技术栈实现，也可以把这份规范直接交给 AI，让它按规则开发。

> 当前版本：**v0.3 Developer Preview**（`rpe-spec-0.3`）。适合产品经理、独立开发者和用 AI 辅助开发的小团队。

## 它解决什么问题

多数背单词工具只回答：**这个词下次哪天复习？**

做产品还要回答：今天有多少词到期？新词还能加多少？复习不完时新词要不要停？先复习还是先学新词？今天忘掉的词要不要再出现？用户点了“熟知”后还算不算在计划里？

RPE 把这些规则拆成两层：

| 层 | 回答的问题 | 是否绑定算法 |
|---|---|---|
| 长期调度层 | 这个词下次哪天复习？ | 可替换，参考策略为 FSRS-3 |
| 每日计划层 | 今天学哪些、各多少、什么顺序？ | 业务规则固定，不依赖具体算法 |

规范不绑定 UI、数据库、平台或编程语言。网页、App、小程序、桌面端都可以按它实现。

## 主要功能

### 1. 安排每个词的复习时间

- 根据“认识 / 模糊 / 忘记”的反馈计算下次复习日期，参考策略为 **FSRS-3**。
- 只有计划内、当天第一次的评分才更新长期记忆；同一天重复评分不会把复习越推越远。
- 忘记默认次日复习，模糊的间隔有上限；“熟知”是终止状态，不等同于 FSRS 的“简单”。

### 2. 生成每天的学习计划

- 每日学习量是**复习量 + 新学量**的总量，默认复习优先、新词补位。
- 复习积压时可以阻止新词进入；支持合并配额和复习/新学分开配额。
- 当天重新生成计划时会扣除已完成部分；可选“提前复习”，把未来到期的词拉进来。

### 3. 控制学习顺序和同日重复

- 复习可按风险、到期时间排序；新词可按词书顺序、随机或词频排序。
- 当天忘记或模糊的词，可以按固定间隔重新插回当前队列。
- 同日重复只影响当前学习队列，不改变长期复习计划。

### 4. 管理单词的完整生命周期

- 单词会经历：未选入 → 待学习 → 学习中 → 熟知 / 暂停 / 删除。
- 支持标记熟知、取消熟知、暂停、恢复和删除后重新加入。
- 删除后重新加入会开启新的学习周期，避免旧记录干扰新进度。

### 5. 保证数据可恢复、可重放

- 所有学习行为都写成不可变事件日志，相同日志重放必须得到相同状态。
- 重复提交同一条命令不会产生重复记录。
- 支持状态导出、日志导出和导入恢复。

## 仓库里有什么

| 目录 | 内容 | 你可以怎么用 |
|---|---|---|
| [docs/](docs/) | 业务规范，当前版本为 [v0.3](docs/01-复习规划引擎-业务描述-v0.3.md) | 作为产品规则和 AI 开发说明 |

仓库里**没有可直接上线的 App**。`conformance/` 里的 Python 只用于验证规则和跑测试，不是生产引擎。网页端案例作为独立项目维护，不在本仓库。

## 怎么用它开发自己的应用

### 1. 先读规范

先看这四节即可开始：

1. [§0 一页摘要](docs/01-复习规划引擎-业务描述-v0.3.md#0-一页摘要)
2. [§3 领域模型](docs/01-复习规划引擎-业务描述-v0.3.md#3-领域模型)
3. [§4 长期调度](docs/01-复习规划引擎-业务描述-v0.3.md#4-长期调度一个单词下一次哪天出现)
4. [§5 每日计划](docs/01-复习规划引擎-业务描述-v0.3.md#5-每日计划今天学什么学多少什么顺序)

### 2. 用 Schema 定数据结构

[schemas/v0.3/](schemas/v0.3/) 已定义单词状态、学习事件、引擎配置、每日计划和导入导出格式。可以直接让 AI 按这些 Schema 生成 TypeScript、Python、Go 或数据库模型，避免各端字段不一致。

### 3. 先做最小闭环

```text
导入词库 → 生成今日计划 → 用户评分 → 保存状态和日志 → 第二天重新生成计划
```

让 AI 实现时，要求它：以规范为唯一业务依据；在代码中引用规则编号（如 `SCHED-001`、`PLAN-015`）；不要自行发明配额、排序和同日重复规则；文字、Schema、测试冲突时，以规范规则编号为准。

### 4. 用一致性测试验收

每次改完核心逻辑，运行：

```bash
python conformance/run_fsrs3_vectors.py
python conformance/business/run_business_scenarios.py
```

预期结果：

```text
OK: 5 vectors passed
23/23 scenarios passed
```

也可以把 [conformance/business/scenarios.json](conformance/business/scenarios.json) 交给 AI，让它翻译成自己项目的单元测试。这些场景就是产品验收用例。

### 5. 最后再做 UI

先做四个页面：**今日**（到期复习、新词、进度）、**学习**（单词卡片、评分、跳过）、**词库**（选词、退词、暂停、熟知）、**设置**（学习量、排序、导入导出）。

UI 只调用引擎的计划和评分接口，不要把配额、排序、到期日计算写进页面组件。

### 给 AI 的起步提示词

```text
请先阅读 docs/01-复习规划引擎-业务描述-v0.3.md、schemas/v0.3/
和 conformance/business/scenarios.json。

我要用 <技术栈> 开发一个背单词应用。请以这份规范作为唯一业务依据，
先实现最小闭环：导入词库、生成今日计划、评分、保存状态和日志。

代码中引用对应规则编号；数据模型遵循 schemas/v0.3/；
每完成一个模块，用 conformance 场景自测；不要自行修改配额、
排序、同日重复和到期日规则。
```
